# BA-G6-CS-U1-L1 — Debugging an Algorithm

**Academy:** Bridge Academy  
**Grade:** 6  
**Subject/Course:** Computer Science / Grade 6 Computer Science  
**Unit:** Unit 1: Algorithms and Debugging  
**Estimated Time:** 30 minutes

## Learning Objective
Students will debug an algorithm by identifying the failing step, explaining the error, fixing it, and testing the result.

## Essential Question
How do careful thinkers find and fix problems in a set of instructions?

## Standards Tags
- CS.G6.ALGORITHMS.DEBUGGING
- CS.G6.PROBLEM_SOLVING.DECOMPOSITION

## Thinking Skill Tags
- computational thinking
- debugging
- evidence-based reasoning
- critical thinking

## Vocabulary
- **algorithm**: A step-by-step set of instructions.
- **debug**: To find and fix an error.
- **bug**: An error that prevents the expected result.
- **sequence**: The order of steps.

## Universal Lesson Flow

### Hook
A robot is supposed to make a sandwich, but it puts peanut butter on the plate before opening the bread. The algorithm has a bug.

**Student Action:** Identify what went wrong in the sequence.

**Success Criteria:**
- Names a sequence error as the likely bug.

### Learning Goal
I can debug an algorithm by finding the step that breaks the intended result.

**Student Action:** Restate debug as find, explain, fix, test.

**Success Criteria:**
- Defines debugging in student-friendly language.

### Mini Teach
An algorithm is a step-by-step set of instructions. Debugging means finding and fixing errors so the steps work.

**Student Action:** Order a simple set of instructions.

**Success Criteria:**
- Explains algorithm and bug.

### First-Principles Breakdown
Break the problem down: What is the input? What should the output be? What steps transform input into output? Which step fails?

**Student Action:** Fill in input, output, steps, failing step.

**Success Criteria:**
- Separates expected output from actual output.

### Worked Example
Example: To log in, steps are enter username, enter password, click sign in. If click sign in happens first, the algorithm fails.

**Student Action:** Mark the bug and fix the order.

**Success Criteria:**
- Correctly reorders the steps.

### Guided Practice
Debug a morning routine algorithm with one missing step.

**Student Action:** Find the missing step and explain why it matters.

**Success Criteria:**
- Explains the bug's effect.

### Critical Thinking Checkpoint
Could an algorithm have more than one possible correct solution? Compare two valid routines.

**Student Action:** Evaluate whether both algorithms reach the same output.

**Success Criteria:**
- Recognizes that different step sets can work if constraints are met.

### Evidence-Based Reasoning Task
Claim: Step 3 is the bug. Evidence: The robot uses an item before it exists. Reasoning: Instructions must be in a logical order.

**Student Action:** Write claim, evidence, reasoning for a bug.

**Success Criteria:**
- Supports bug claim with evidence from steps.

### Interpretation / Discussion Task
Discussion frame: 'I think the bug is ___ because ___. I would test it by ___.'

**Student Action:** Use academic dialogue to defend a debugging choice.

**Success Criteria:**
- Uses because and test language.

### Active Practice
Debug a block-code style algorithm for moving through a maze.

**Student Action:** Choose the incorrect step and replace it.

**Success Criteria:**
- Produces a working sequence.

### Retrieval Check
Without looking, name the four debugging moves.

**Student Action:** Recall find, explain, fix, test.

**Success Criteria:**
- Recalls the debugging cycle.

### Feedback
Feedback names whether the mistake was sequence, missing step, wrong condition, or unclear instruction.

**Student Action:** Tag the mistake type and revise.

**Success Criteria:**
- Correctly tags at least one bug type.

### Reflection
What clue helped you find the bug? What will you check first next time?

**Student Action:** Complete a debugging reflection.

**Success Criteria:**
- Names a reusable strategy.

## Quiz and Answer Key

- **BA-G6-CS-U1-L1-Q1** (mc): What is an algorithm?  
  - Correct/Expected: A step-by-step set of instructions  
  - Explanation: Algorithms tell a system what steps to follow.

- **BA-G6-CS-U1-L1-Q2** (mc): What does debugging mean?  
  - Correct/Expected: Finding and fixing errors  
  - Explanation: Debugging means find, explain, fix, and test.

- **BA-G6-CS-U1-L1-Q3** (mc): Which is usually checked first when debugging a sequence?  
  - Correct/Expected: Whether the steps are in logical order  
  - Explanation: Sequence bugs happen when steps are missing or out of order.

- **BA-G6-CS-U1-L1-Q4** (mc): A robot pours cereal before getting a bowl. What kind of bug is likely?  
  - Correct/Expected: Sequence error  
  - Explanation: The robot uses the bowl before it exists in the steps.

- **BA-G6-CS-U1-L1-Q5** (mc): What should happen after you fix a bug?  
  - Correct/Expected: Test the algorithm  
  - Explanation: Testing checks whether the fix actually works.

- **BA-G6-CS-U1-L1-Q6** (mc): Which evidence best proves Step 2 is a bug?  
  - Correct/Expected: The output fails right after Step 2  
  - Explanation: Evidence must connect the step to the failure.

- **BA-G6-CS-U1-L1-Q7** (short_answer): Explain the debugging cycle in four words or short phrases.  
  - Correct/Expected: Find, explain, fix, test.  
  - Explanation: These are the core moves of debugging.

- **BA-G6-CS-U1-L1-Q8** (cer): Write a claim and evidence for this bug: Step 1 says 'click submit' before entering a name.  
  - Correct/Expected: Claim: Step 1 is the bug. Evidence: The name has not been entered yet, so submit cannot work correctly.  
  - Explanation: The answer should connect the failing step to the expected output.

- **BA-G6-CS-U1-L1-Q9** (explain): Why is testing important after a fix?  
  - Correct/Expected: Testing shows whether the new steps produce the correct output.  
  - Explanation: A fix is not proven until it is tested.

- **BA-G6-CS-U1-L1-Q10** (short_answer): Give one example of an algorithm outside computers.  
  - Correct/Expected: A recipe, morning routine, or directions to a place.  
  - Explanation: Algorithms are step-by-step instructions in many contexts.

- **BA-G6-CS-U1-L1-Q11** (explain): Explain one important idea from debugging an algorithm using your own words.  
  - Correct/Expected: A strong answer accurately explains debugging an algorithm and includes a reason or example.  
  - Explanation: This checks whether the student can explain debugging an algorithm, not just recognize it.

- **BA-G6-CS-U1-L1-Q12** (explain): Explain one important idea from debugging an algorithm using your own words.  
  - Correct/Expected: A strong answer accurately explains debugging an algorithm and includes a reason or example.  
  - Explanation: This checks whether the student can explain debugging an algorithm, not just recognize it.

## Reteach Path
Debugging is not guessing. First find where the steps stop matching the goal.

- State the goal
- List the steps
- Find the first failing step
- Explain why it fails
- Fix one thing
- Test again

## Challenge Path
- Design a maze algorithm with one hidden bug and write an answer key.
- Compare two working algorithms and decide which is clearer.
- Debug a real-life routine such as packing a backpack.
