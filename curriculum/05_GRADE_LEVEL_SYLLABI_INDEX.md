# 05 — Grade-Level Syllabi Index

> **Project context:** K–12 Learning App Suite with Foundation Academy (K–5), Bridge Academy (6–8), and Scholar Academy (9–12). The platform is a thinking-development and retention platform, not a video/flashcard library. Every curriculum artifact must support the core loop: **Teach → Break Down → Think → Discuss → Interpret → Prove → Practice → Retrieve → Space → Reflect → Adapt → Apply**.

## Purpose

This document lists every grade-level syllabus that must eventually exist and defines what each syllabus must contain. Grade-level syllabi are the year-long learning contracts for students, parents, teachers, and the app.

## Locked Core Pillars

Every syllabus, unit, lesson, assessment, activity bank, and review item must support the locked core pillars:

1. Standards-Aligned Curriculum
2. First-Principles Problem Solving
3. Critical Thinking
4. Discussion & Academic Dialogue
5. Interpretation
6. Evidence-Based Reasoning
7. Metacognition
8. Retrieval + Spaced Retention
9. Inquiry-Based Learning
10. Computational + Systems Thinking
11. Project-Based Application
12. Adaptive Mastery + Feedback
13. Fun + Motivation
14. Accessibility + Inclusive Learning
15. Safe Child-Centered Design

## Required Syllabus Sections

Every grade-level syllabus must include:

1. Grade identity and developmental profile.
2. Full-year learning goals.
3. Subject/course list.
4. Unit sequence by subject/course.
5. Core vocabulary and concept families.
6. Thinking skills focus.
7. Required projects and assessments.
8. Memory Vault priorities.
9. Reteach/intervention expectations.
10. Challenge/enrichment expectations.
11. Parent/teacher support notes.
12. Accessibility considerations.
13. Safety and communication limits.
14. Status and revision history.

## MVP Grade 3 Syllabus Requirements

Grade 3 must emphasize:

- Transition from learning to read toward reading to learn.
- Multiplication/division foundations.
- Main idea and evidence.
- Scientific observation and life cycles.
- Community, geography, roles, and civic thinking.
- Short written explanations.
- Memory Vault fluency and vocabulary review.

## MVP Grade 6 Syllabus Requirements

Grade 6 must emphasize:

- Middle-school independence.
- Ratios, rates, rational numbers, and expressions.
- Text evidence and theme.
- Earth systems and scientific models.
- Ancient civilizations and geography.
- Study skills and organized notes.
- Structured discussion and evidence use.

## MVP Grade 9 Syllabus Requirements

Grade 9 must emphasize:

- High-school course dashboard model.
- English 9, Algebra I, Biology, and World History I.
- Claim-evidence-reasoning.
- Variables, expressions, systems, and models.
- Biology as systems thinking.
- River valley civilizations and historical evidence.
- Portfolio-ready outputs.

## Grade-Level Syllabus Acceptance Criteria

A grade-level syllabus is complete when it:

- Covers all subjects/courses for the grade.
- Names all units in order.
- Identifies at least one project per major subject.
- Identifies Memory Vault targets for key skills.
- Lists assessments and mastery expectations.
- Includes parent/teacher notes.
- Can be converted into course syllabi and unit maps without guesswork.

## Universal Review Checklist

Before this document is marked **Approved**, verify that it:

- Aligns to the three-academy structure.
- Supports the full learning loop, not just passive content.
- Identifies MVP scope versus later expansion.
- Includes implementation rules Codex can follow.
- Includes content QA expectations.
- Includes accessibility and child-safety considerations where relevant.
- Connects to standards tags, thinking skill tags, Memory Vault review, mastery bands, and parent/teacher reporting.
- Avoids scope creep by clearly naming what is out of scope for MVP.

Use these workflow labels for all content artifacts referenced here:

| Status | Meaning |
|---|---|
| `planned` | Artifact exists in the backlog only. |
| `drafting` | Writer/curriculum designer is creating first draft. |
| `needs_review` | Draft is ready for academic/product review. |
| `needs_revision` | Review found required fixes. |
| `approved` | Artifact is ready for app implementation. |
| `implemented` | Artifact exists in the repo/app. |
| `tested` | Artifact has passed QA checks. |
| `published` | Artifact is live or release-ready. |
| `archived` | Artifact is deprecated but preserved for history. |
